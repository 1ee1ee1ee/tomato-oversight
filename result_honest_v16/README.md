## 판정: ❌ 게이트·배포·직렬 모두 미달 → **역할 재배치(v3.2) 유지 확정**

| 지표 | v16 결과 | 기준 | 비고 |
|---|---:|---:|---|
| 격자 latch (12칸 평균, 240판) | **0.467** | ≥ 0.85 | v15는 같은 게이트에서 0.569 |
| 최악 칸 | 0.2 | (보고용) | v15는 0.0 — 구멍은 메워짐 |
| deploy full / alive (30판) | **0.0 / 2.07** | ≥ 4.3 | 자체 배포 환경(배턴터치 ON) |
| **직렬 배포 alive @f=1.0** (checkpoints 10개 재선정) | 스크리닝 최고 2.50 (1M, 4시드) → **정밀 1.62** (8시드×2f) | **≥ 4.8** | 최종 직렬 순위: v13 2.50 > v14 1.75 > **v16 1.62 = v15 1.62** |

**학습 곡선**: 0.16 → 0.36(300k) → ~0.3 정체 → 0.43(900k). 후반 상승은 왔지만
게이트의 절반 수준에서 끝. 흥미로운 것은 **실패의 모양**이 v15와 정반대라는 점 —
v15는 "한 점만 만점"(phase0·5마리 1.0, 나머지 0), v16은 **전 축 균등하게-낮음**
(phase 0.40~0.58, alive 0.40~0.59, 최악 칸 0.2). 즉 3축 개방은 의도대로 작동했고
(phase 특화 소멸·시체 칸 측정·넓은 퍼짐 노출 — 로그로 확인), **같은 DQN 레시피의
용량/최적화가 넓어진 과제를 못 따라간 것**이 결론이다.

## 이 run이 확정한 것

1. **위기 3축 진단(v16의 기여)은 옳았다** — v15의 "한 점 게이트" 문제를 열자
   실제 난이도가 드러났다. 격자 게이트·게이트-학습분포 결합(env 함수 직접 호출)·
   회귀 스텁 방법론은 이후 버전이 그대로 물려받을 자산.
2. **v13~v16 네 버전 모두 직렬 배포 요구(전판 5/5)에 크게 미달** (2.50 / 1.75 /
   1.62 / 1.62). 이 과제(임의 phase·시체·퍼짐에서 500 step 내 연속 순회 구조 ~9회
   무결 완수)는 **현 DQN 레시피의 한계 밖**이라는 4중 증거.
3. 따라서 **적응형 치터의 처치 축 = 스크립트+스크립트(v3.2)를 동결**한다.
   학습 모델은 학습된 맥락(정직 에피소드 = v13, 배신형 = v13→cheater_v1)에서
   그대로 쓴다. 감시자(연구 대상)는 상대의 학습 여부를 관측하지 않는다.

## (후순위) 학습 정직으로 축을 되찾고 싶다면

RL 재시도보다 **행동 복제(BC)**가 유망하다: 스크립트 정직의 구조 순회는 25~32
step짜리 결정적 행동이라, (관측→행동) 지도학습으로 격자 전 칸을 채우는 편이
DQN의 희소 보상 신용 할당보다 쉽다. 감시자 완성 후의 확장 과제로 남긴다.
