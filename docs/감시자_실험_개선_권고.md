## 0. 요약

r2_run2로 **"감시자가 실모델 로봇 상대로 학습되고, 주기 대조군을 이기며, held-out에
일반화된다"**는 것이 확인됐다. 그러나 이대로는 **발표 결과로 내놓기 부족**하다. 세 층위의
공백이 있고, 우선순위대로 정리한다.

| 순위 | 항목 | 성격 | 비용 |
|---|---|---|---|
| 🔴 1 | 체제1 학습 | 없으면 연구 질문 미답 | 학습 1회 |
| 🔴 2 | 다중 시드(3~5) | n=1 통계 무효 위험 | 학습 ×N |
| 🟠 3 | (c,w) 스윕 → 파레토 프론티어 | "한 점"→"프론티어 지배" | 평가만(학습 재사용) |
| 🟠 4 | 체제2 반응성 진단(K별) | 왜 체제2>체제1인지 실증 | 분석만 |
| 🟢 5 | never-audit 탈출 안정화 | 다중 시드 견고성 | ✅ 반영됨 |
| 🟢 6 | 신뢰구간 보고 | 유의성 | ✅ 반영됨 |
| 🟢 7 | 배포 사전확률 민감도 | 정직성 | 평가만 |

r2_run2 핵심 수치(참고): 학습 감시자 평균 비용 **13.75 / 감사 3.01**, 대조군 N500
17.94 / 9.48, never 243.1. 배신 전 시나리오 **적발률 100%**, 정직 허탕 **5.85**(vs N500
20·always 100). held-out K(1800·6200) 지연 평균 311 ≈ 학습 K 295 → **암기 아님**.

## A. 타당성 공백 — 없으면 결과가 성립하지 않음

### 1. 체제1이 없다 = 연구 질문에 답이 없다

프로젝트 명제는 **"체제1 vs 체제2 = 행동 로그의 가치"**다. 지금 있는 것은 체제2뿐이고,
"체제2가 주기 대조군을 이긴다"는 **필요조건이지 헤드라인이 아니다.** 헤드라인은
**체제2 − 체제1 격차**다. 체제1 없이는 결론 슬라이드가 빈다.

### 2. 학습 시드가 1개다

최종 평가는 20시드지만 **학습된 모델 자체가 n=1**이다. honest v13/v14에서 "선정 0.6 →
재평가 0.3"의 선정 분산에 이미 데였다. 감시자도 운 좋은/나쁜 단일 시드일 수 있다.
**3~5 시드 학습, 평균±신뢰구간 보고**가 필수. 4번(never-audit 함정)과 겹치면 일부 시드는
아예 학습에 실패할 수 있다(→ §C.5로 완화).

## B. 지금은 "한 점" — "프론티어"로 재구성해야 강해진다

### 3. 비용모델 (c=1, w=0.01)은 임의의 한 점이고, 그 점이 지연을 악화시킨다

r2_run2에서 **학습 감시자의 적발 지연이 대조군보다 길다**(k0: 414 vs 295). 규칙 목표는
"지연은 대조군과 *비슷*하면서 검사는 훨씬 적게"인데, 현재는 "지연은 더 나쁘고 검사만
훨씬 적게"다. 이는 결함이 아니라 **`c:w` 비율이 정한 작동점**이다 — w를 올리면(지연을
더 비싸게) 감시자가 더 일찍 감사한다.

**권고**: `(c, w)`를 스윕하고 **"검사수 vs 적발지연" 파레토 프론티어**를 그려, 그 위에서
학습 감시자가 **주기 대조군 가족 전체를 지배**함을 보인다. 단일 점보다 압도적으로 강하다.
도구: [`overseer_v2/pareto_sweep.py`](../overseer_v2/pareto_sweep.py) — 학습된 체크포인트를
재학습 없이 여러 주기 N과 함께 재평가한다(비용은 reward_scale 무관이라 재계산 가능).

> 이것이 사실상 논문의 킬러 그림 한 장: x=검사수, y=적발지연, 대조군은 곡선, 학습
> 감시자(체제1·체제2)는 그 아래 점.

### 4. K별로 쪼개면 체제2가 왜 이겨야 하는지가 드러난다

r2_run2 체제2를 K별로 보면:

| 시나리오 | 학습 감시자 비용 | 대조군 N500 비용 |
|---|---:|---:|
| 배신 k0 (이른 배신) | **18.8** ❌ | 13.4 |
| 배신 k4000 | 9.6 ✅ | 21.1 |
| 배신 k6000 (늦은 배신) | **16.0** ✅ | 24.4 |

**늦은 배신에서 압승**(정직 구간을 안 뒤짐), **이른 배신에서 오히려 패배**(초기에 충분히
공격적이지 않음). 즉 학습 감시자는 **K-평균에 최적화됐을 뿐 행동에 *반응*하지 못한다.**
그런데 반응성이야말로 체제2(행동 로그)가 줘야 할 능력이다 — "로봇이 O 구역에 가고 물을
안 주면 K와 무관하게 즉시 감사". 지금 체제2가 이걸 못 한다는 것은 **행동 신호를 아직 덜
활용**한다는 뜻이며(1시드·60k 부족 또는 행동 피처가 약함), 동시에 **체제2가 체제1을 이겨야
하는 정확한 메커니즘**을 짚어준다. 진단 방법: 체제1·체제2를 K별로 비교해, 체제2가 이른
배신에서 격차를 얼마나 좁히는지 측정한다.

## C. 정밀도·견고성

### 5. never-audit 지역최적 탈출 안정화 (반영 완료)

r2_run2는 45k까지 감사 0회에 갇혔다가 겨우 탈출했다. 다중 시드에서는 일부가 못 탈출할
위험이 있다. **해법: 학습 초반 리플레이에 AlwaysAudit 에피소드를 강제 주입**("감사→적발→
종료→피해회피" 경험을 미리 심기). 정책을 왜곡하지 않는다(에이전트는 여전히 자기 행동을
선택). `train_overseer.py --warmup-episodes`(기본 8)로 반영했다. 스모크: 워밍업 시 3k
step에 이미 감사 2회·비용 5.7(예전 45k까지 0회).

### 6. 신뢰구간 (반영 완료)

`eval_policy`가 `cost_ci95` / `audits_ci95`(95% CI 반폭)를 산출하도록 했다. "13.75 vs
17.94"가 유의한지 함께 보고한다.

### 7. 배포 사전확률 민감도

감시자는 정직:배신 = 50:50에 맞춰 감사율을 보정했다. 실제 비율이 다르면 최적 감사율도
달라진다. eval에서 honest_prob를 바꿔 민감도 곡선 하나를 보이면 정직성이 올라간다(평가만
필요, 학습 불필요).

## E. 실행 계획 (권고)

v3.4 재실행 시 **처음부터 다음을 함께** 돌려 1·2번을 공짜로 흡수한다.

```bash
# 체제1·체제2 × 3시드 (--seed 0,1,2), 워밍업 기본 on
for R in 1 2; do for S in 0 1 2; do
  python train_overseer.py --regime $R --seed $S --total-steps 100000 \
    --output-dir "/content/drive/MyDrive/result_overseer_v2/r${R}_s${S}"
done; done
```

학습 후(재학습 불필요):

```bash
# 파레토 프론티어: 대조군 가족 vs 학습 감시자(시드들)
python pareto_sweep.py --regime 2 \
  --model r2_s0/overseer_r2_best.pt --model r2_s1/overseer_r2_best.pt \
  --model r2_s2/overseer_r2_best.pt --periods 100,250,500,1000,2000 --out pareto_r2.csv
```

최종 산출물: **(x=검사수, y=적발지연) 프론티어 그림 + 체제1/2 격차 표(CI 포함) +
held-out 일반화 + 정직 허탕률**. 이 넷이 발표의 결론이다.
