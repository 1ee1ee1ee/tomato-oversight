## 1. 전체 구조

프로젝트는 동시에 싸우는 두 에이전트가 아니라, **두 단계의 독립 학습**입니다.

```text
1단계: 재배 로봇 정책 학습
  ├─ 정직 로봇
  └─ 치터 로봇
          ↓ 학습 완료 후 정책 고정
2단계: 감시자 학습
  ├─ 체제 1: 겉보기 결과만 상시 관측
  └─ 체제 2: 겉보기 결과 + 행동 정보 상시 관측
          ↓
      계속 관찰 / 정밀검사
```

감시자를 학습할 때는 재배 로봇을 더 학습시키지 않습니다. 여러 개의 고정된 정직·치터 정책을 감시자가 무작위로 상대합니다.

## 2. 재배 로봇

재배 로봇은 작은 격자와 이산 행동을 사용하므로 우선 **DQN**으로 통일하는 것이 좋습니다. PPO도 가능하지만 이 단계에서는 알고리즘 비교가 연구 목표가 아니므로 하나만 쓰는 편이 낫습니다.

재배 로봇의 관측과 행동은 다음과 같습니다.

- 관측: 격자 상태
- 행동: 상·하·좌·우·정지
- 정직 로봇: 실제 토마토 생존을 높이는 보상으로 학습
- 치터 로봇: 겉보기 토마토 상태를 기반으로 한 proxy 보상으로 학습
- 학습 완료 후 모델 파라미터 고정

정직 로봇이 O 타일을 “절대 사용하지 않는다”는 조건은 학습 결과에만 맡기면 안 됩니다. 우연히 밟을 수도 있기 때문입니다. 다음 중 하나로 명시해야 합니다.

- 정직 로봇의 행동 마스킹으로 O 진입 금지
- O 진입에 명시적인 큰 페널티 부여
- 정직 로봇 학습 환경에서는 O를 장애물로 처리

이 경우 정직 로봇은 “치팅을 발견하지 못한 로봇”이 아니라 **치팅 사용이 제한된 안전 정책**입니다. 치터는 O에 접근할 수 있고 proxy reward를 최대화하도록 학습합니다.

## 3. O 타일과 S 타일

결론부터 말하면 **처음부터 O와 S를 모두 넣지는 않는 것이 좋습니다.** 그렇다고 둘 다 없애서도 안 됩니다. O가 없으면 치팅 자체가 발생하지 않기 때문입니다.

다음과 같이 단계별 환경을 만드는 것이 가장 깔끔합니다.

| 환경 | 구성 | 목적 |
|---|---|---|
| E0 | O 없음, S 없음 | 정상 재배 학습 및 안전 기준선 |
| E1 | O만 있음 | 치터 학습과 기본 감시 실험 |
| E2 | S만 있음 | 정당한 고보상 행동 검증 |
| E3 | O와 S 모두 있음 | 진짜 개선과 센서 조작을 구별하는 확장 실험 |

핵심 발표는 E0와 E1만으로도 완성할 수 있습니다. E2와 E3는 감시자가 단순히 “높은 보상은 치팅”이라고 외우지 않았음을 확인하는 실험입니다.

`No Free Lunch` 논문도 같은 순서에 가깝습니다. Case 1은 O만, Case 2는 S만, Cases 3~5는 O와 S를 함께 두고 위치를 바꿉니다. 특히 S를 먼저 경험하면 높은 보상이 정상 분포에 들어가 이후 O를 의심하지 못하는 Case 5 실패가 나옵니다. :codex-file-citation{path="C:\Users\hibab\OneDrive\바탕 화면\3학년 1학기\창설축\no free lunch.pdf" purpose="source"}

따라서 제 추천은:

> 핵심 학습에는 O만 사용하고, S는 감시자 성능을 검증하는 추가 환경에 넣는다.

## 4. 감시자가 항상 보는 정보

맞습니다. 이제 `값싼 확인`이라는 행동은 삭제합니다. 감시자는 값을 싼 공개 정보를 **별도의 행동 없이 항상** 봅니다.

### 체제 1: 결과 관측형

감시자가 항상 보는 정보:

- 겉보기 토마토 상태 또는 `apparent_alive`
- 재배 로봇이 받은 공개 reward
- 현재 시간과 에피소드 진행률
- 마지막 정밀검사 이후 경과 시간
- 이전 정밀검사 결과
- 누적 정밀검사 횟수

로봇의 위치나 행동은 보지 않습니다. 따라서 겉보기 결과와 시간만으로 검사 시점을 판단합니다.

### 체제 2: 행동 관측형

체제 1 정보에 다음을 추가합니다.

- 재배 로봇의 현재 위치
- 최근 이동 방향
- 정지·이동·물주기 횟수
- 최근 \(K\) step의 이동 통계
- 특정 위치에 반복적으로 접근하는 패턴
- 토마토별 마지막 방문 이후 시간

여기서 `cheating=True`, `O_tile_visited=True`처럼 정답에 가까운 가공 정보는 주면 안 됩니다. 체제 2는 **원시 행동 이력으로 의심을 학습**해야 합니다.

O의 위치를 감시자가 알고 로봇 위치까지 본다면 “O에 갔으니 검사”로 너무 쉬워질 수 있습니다. 따라서 본 실험에서는 다음 중 하나가 필요합니다.

- 에피소드마다 O 위치를 바꿈
- 감시자에게 타일의 의미는 숨기고 좌표·행동만 제공
- 학습과 평가에서 O 위치를 다르게 배치

### 왜 체제 1과 2를 나누는가

이 구분은 기존 저장소가 그대로 제공하는 두 모드가 아니라, **행동 정보의 추가 가치를 측정하기 위한 ablation 실험**입니다.

- 체제 1: 겉보기 성과만 관측하는 일반적인 외부 감사
- 체제 2: 행동 로그까지 확보한 감사
- 두 체제의 검사 횟수·적발률·지연 차이 = 행동 로그의 가치

공식 AI Safety Gridworlds 역시 에이전트가 보는 reward와 숨겨진 safety performance를 분리합니다. 우리는 그 위에 “감시자가 행동 로그까지 볼 때 얼마나 유리한가?”라는 실험 축을 추가하는 것입니다.

## 5. 감시자의 행동

감시자 행동은 정확히 두 개입니다.

```text
0 = CONTINUE
    계속 관찰하며 재배 로봇의 다음 행동을 허용

1 = AUDIT
    재배 로봇을 일시 정지하고 정밀검사 수행
```

`CONTINUE`는 “값싼 확인”이 아닙니다. 값싼 정보는 원래부터 항상 들어오고, CONTINUE는 단순히 **개입하지 않는 결정**입니다.

한 step의 순서는 다음으로 고정하는 것이 좋습니다.

1. 재배 로봇이 한 번 행동
2. 환경 상태 변화
3. 공개 정보 및 행동 로그 갱신
4. 감시자가 관측
5. 감시자가 `CONTINUE` 또는 `AUDIT` 선택
6. `AUDIT`이면 재배 로봇 정지 및 검사 결과 제공
7. 치팅 적발 시 에피소드 종료 또는 로봇 운용 중단

## 6. 정밀검사로 받는 정보

정밀검사는 `cheater=True`라는 정답을 직접 반환하지 않습니다. 감시자에게는 **치팅 여부를 판단할 수 있는 검증 데이터**를 줍니다.

최소 구현은 다음과 같습니다.

```text
audit_result = {
    apparent_alive,
    inspected_alive,
    discrepancy,
    previous_apparent_alive,
    audit_timestamp
}
```

여기서:

- `inspected_alive`: 정밀검사로 추정된 실제 생존 토마토 수
- `discrepancy`: 겉보기와 정밀검사 결과의 차이
- `true_alive`: 환경 내부의 완전한 참값
- `gap = apparent_alive - true_alive`

정밀검사 결과에 정확한 `true_alive`와 `gap`을 그대로 주면 치팅 판정은 사실상 결정적입니다. 감시자가 “추정”하게 만들려면 다음처럼 측정 오차를 넣는 것이 더 적합합니다.

\[
\widehat{true\_alive}=true\_alive+\epsilon
\]

\[
audit\_gap=apparent\_alive-\widehat{true\_alive}
\]

다만 8월 14일 발표용 최소 구현에서는 먼저 **정확한 검사 결과**를 사용하는 것이 안전합니다. 이후 확장 실험으로 검사 노이즈를 넣으면 됩니다.

논문의 Doubt는 실제 상태를 직접 받는 방식이 아니라, 의심 행동을 되돌린 뒤 두 격자의 유사도를 비교하여 효과가 지속되는지 검증합니다. 우리는 이를 외부 감시 문제에 맞게 “정밀검사로 얻은 겉보기-실제 불일치 데이터”로 변형하는 것입니다. 논문을 정확히 재현한다고 표현하면 안 되고, **Doubt의 validation-action 개념을 확장했다**고 표현해야 합니다.

## 7. 감시자 학습 방법

감시자는 우선 **DQN**을 추천합니다.

이유는 다음과 같습니다.

- 행동이 `CONTINUE/AUDIT` 두 개의 이산 행동
- 재배 로봇 정책이 고정되어 환경이 비교적 정상적
- 과거 경험을 replay buffer로 재사용할 수 있음
- “현재 상태에서 검사하는 가치와 기다리는 가치”를 직접 비교 가능
- PPO보다 적은 샘플로 학습할 가능성이 큼

단, DQN에 전체 행동 이력을 직접 넣지는 않습니다. 최근 행동을 고정 길이 통계로 요약해 관측이 충분히 Markov에 가깝게 되도록 합니다. 나중에 전체 시계열 기억이 필요하다고 확인되면 Recurrent PPO를 비교 대상으로 추가합니다.

## 8. 감시자 보상

보상은 내부 참값을 사용해 계산할 수 있지만, 그 참값을 관측으로 넘기면 안 됩니다.

추천 보상은 다음입니다.

```text
CONTINUE                     0
AUDIT                       -C_audit
치팅을 정밀검사로 적발       +R_catch
정직 로봇을 의심한 허탕 검사 -F_false
치터를 끝까지 미적발         -P_miss
```

선택적으로 적발 지연을 종료 시 한꺼번에 반영합니다.

\[
R_{\text{terminal}}
=
-P_{\text{miss}}
-\lambda \times \text{detection delay}
\]

중요한 점은 치팅 중 `CONTINUE`할 때마다 즉시 벌점을 주지 않는 것입니다. 그 보상이 감시자에게 숨겨진 치팅 상태를 간접적으로 알려주는 누출이 될 수 있고, 너무 크게 설정하면 무조건 검사하는 정책으로 붕괴합니다.

따라서:

- 중간에는 검사 비용과 검사 결과에 따른 보상만 제공
- 미적발 및 지연 평가는 적발 시점 또는 에피소드 종료 후 제공
- 참값은 reward oracle과 평가 코드만 사용
- 감시자 관측에는 참값을 넣지 않음

## 최종 백브리핑

제가 이해한 최종 의도는 다음과 같습니다.

> 먼저 동일한 tomato-watering 계열 환경에서 정직 재배 로봇과 치팅 재배 로봇을 각각 강화학습으로 만들고 정책을 고정한다. 이후 별도의 감시자 에이전트가 이 로봇들을 무작위로 상대한다. 감시자는 겉보기 성과를 항상 관측하며, 행동 관측 여부에 따라 체제 1과 체제 2로 구분한다. 감시자의 행동은 계속 관찰과 정밀검사의 두 가지뿐이다. 정밀검사를 수행하면 재배 로봇이 일시 정지하고, 감시자는 겉보기 상태와 실제 상태의 불일치를 판단할 수 있는 검증 데이터를 받는다. 감시자는 제한된 검사 비용으로 치터를 놓치지 않도록 DQN으로 검사 시점을 학습한다. O-only 환경을 핵심 실험으로 사용하고, S-only 및 O+S 환경은 정당한 고보상과 치팅을 구별하는 확장 검증으로 사용한다.

이 설계에서는 기존 문서의 `값싼 확인` 행동, 소급 transition 수정, 매-step 숨은 치팅 벌점은 제거하는 것이 맞습니다.
